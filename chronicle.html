The shape of the thing

One question, one button, and the honesty to say what it cannot put back

A session, not a log

Chronicle never shows you a stream of events. Raw observations are an implementation detail; the unit you see, search, name, pin and restore is always a work session with a start, an end, and a subject.

Reconstruct, don’t relaunch

Opening five apps is not restoring a workspace. The editor comes back on the right branch with the right file, the browser as one window of the right tabs, the terminal already in the right directory. Anything less is a shortcut folder.

Local, or nothing

Every observation stays in one encrypted file on the machine that made it. No account, no sync, no telemetry, no cloud fallback. If a feature would need a server, Chronicle does not ship it.

The loop this serves: work → Chronicle remembers → something interrupts → you come back → you see where you stopped → you restore → you keep working. Anything that does not shorten the gap between “you come back” and “you keep working” does not belong in the product.

Sessions

How a day of window switching becomes four things you recognise

A session is a stretch of time where the same work was happening. Chronicle finds the edges from behaviour, not from a timer, and revises them as more of the day arrives.

Boundary rules

SignalRuleEffect
IdleNo focus change, no input for 12 minutesSoft boundary — closes the session if nothing resumes
Lock, sleep, log outAny of themSoft boundary, timestamped
Crash or forced restartDaemon did not write a clean shutdown recordHard boundary; session flagged Interrupted and surfaced first on next login
Context switchOver 70% of the focused window set turns over within 10 minutes, with no shared project rootSplit into two sessions
Return to workA previously dominant project root regains focus within 45 minutesStitch back — one session with a gap, not two sessions
Short noiseSession under 4 minutes, or fewer than 3 distinct artifactsDiscarded; a glance at Slack is not a session

Every threshold here is a default, and every one is editable in Settings → Sessions. People who work in 20-minute bursts and people who sit on one problem for six hours both need to recognise their own days in the list.

How a session gets its name

Names come from structure, never from the contents of your documents. Chronicle takes the first of these that resolves, then keeps the name stable once you have seen it:

1   The dominant repository or project root — spotted-android → “Building the Android App”
2   The git branch, when one branch held most of the time — feature/login-otp → “Login & OTP”
3   The dominant design file or document title
4   The most-visited site’s topic cluster — “Research — on-device inference”
5   Otherwise the app mix and time of day — “Thursday morning — mixed”

Rename any session with ⌘R. A renamed session is never re-titled automatically, and the name you chose becomes a search term.

Artifacts are shared across sessions, so “every session that touched this Figma file” is one join, and deleting an artifact removes it everywhere at once.

What it sees

Enough to put the desk back, and deliberately nothing more

Chronicle records pointers, not contents. A path, a URL, a branch name, a page number, a window frame. It is the difference between a bookmark and a photocopy, and it is the whole privacy posture in one sentence.

Never, under any setting

Keystrokes and key logging. Clipboard contents. Screenshots or screen recording. Passwords, tokens, or anything typed into a secure field. Camera or microphone. Any window belonging to a password manager, a banking or health app, or a private browsing session. There is no preference that turns these on, because the code to capture them is not in the binary.

Window titles are the sharp edge

A title bar is the one field that leaks content — a document name, a patient record, an email subject. Chronicle treats it as sensitive by default:

·  Titles are matched against secret patterns (keys, tokens, long hex) and dropped before they are written.
·  Apps can be set to title-blind — Chronicle stores that the app was open and for how long, and stores the title as the app name.
·  URLs are stripped of query strings unless the path alone would not identify the page, and always stripped of anything matching a token pattern.

The button

Restore Workspace

The operating system decides how much of a workspace can genuinely come back. Chronicle’s job is to reach the highest fidelity each app allows, and to be plain about where it lands.

The fidelity ladder

LevelWhat you getHow
ExactThe app reopens in the state it was leftNative workspace or session APIs — a VS Code workspace file, a JetBrains project, a browser tab set written through the Chronicle extension, an AppleScript-composed Safari window
Deep linkThe app opens straight to the artifactfigma://file/…?node-id=, xed project.xcodeproj, slack://channel, a terminal opened in the right directory
OpenThe file opens in its default app; position is not recoverablePlain open / start on the path
Needs youChronicle cannot act aloneA card with the path, URL, or command and a copy button — a stopped Docker stack, a VPN, an app that is not installed on this machine
MissingThe thing is goneLast known path, when it was last seen, and a search of the current disk for a file with the same name

The badge on every row of the session detail is this ladder. You know before you press the button which twelve of fourteen things will land.

What happens when you press it

01

Plan

Resolve every artifact against the current machine. Does the path still exist? Is the app installed? Is this display still attached? Deduplicate, decide a fidelity level per item, and group by application.

02

Confirm

Show the plan with every item checked and nothing launched yet. Uncheck what you do not want. ↵ proceeds. Turn on Restore without asking and this step is skipped for sessions you have restored before.

03

Make room

Optionally open a new Space or virtual desktop, so restoring yesterday never buries what you are doing right now. On by default when more than four windows are coming back.

04

Launch in order

Editors and terminals first, because they are slowest to become ready; browsers last, because they steal focus. Each app gets a readiness handshake with a timeout, and a stalled app never blocks the rest of the plan.

05

Deepen

Once an app reports ready, send it the state: open the workspace, jump to the file and line, compose the tab set into one window, cd the terminal. This is the step that separates Chronicle from a folder of aliases.

06

Place

Restore window frames per display. If the display arrangement changed — the external monitor is not here today — remap proportionally onto what is attached, never off-screen.

07

Report, and offer to undo

A receipt: what came back, at what fidelity, what did not and why. Undo Restore stays available for ten minutes and closes only the windows Chronicle opened.

Two rules that never bend

Commands are typed, never run

A terminal comes back in the right directory with the last command pre-typed at the prompt and the cursor at the end. Chronicle does not press Return for you. rm -rf, a deploy, a migration — the machine cannot tell which of yesterday’s commands is safe to repeat, so it never guesses.

Restore is additive and reversible

Chronicle never closes, moves, or replaces a window you already have open. It only adds, it tracks exactly what it added, and Undo removes precisely that set.

How it resolves

Four extractors run over the phrase — time (“yesterday”, “last night”, “Monday”, “last”), kind (figma, website, project, terminal, session), subject (matched against project roots, branch names, file names, session titles and domains via SQLite FTS), and intent (show, open, restore). What is left over becomes a full-text search. An unparseable query still returns ranked sessions rather than an error.

Ranking favours focus time over visit count — the tab you stared at for forty minutes beats the twelve you opened and closed.

Privacy

A record you can read, edit, and destroy

A tool that watches your desk all day only works if you never wonder what it has. So the record is legible, the controls are per-app, and deletion is real deletion.

Three states per app, one row each, and a shipped deny list covering password managers, banking, health and messaging so the first run is already conservative.

One encrypted file, on this machine

SQLite at ~/Library/Application Support/Chronicle/, encrypted at rest with a key held in the system keychain and released on unlock. No account, no server, no sync, no crash reporting. Backup is an explicit export you carry yourself.

Show me everything you have

Any session opens to its raw rows — every observation, its source, and its timestamp. Nothing about the record is summarised away from you, and the export is plain JSON.

Forgetting is a first-class verb

90-day rolling retention by default, adjustable to 7 days or forever. Delete one item, one session, one day, or everything about one project. Forget the last hour sits in the menu bar for the moment you realise you should not have been recorded. Deletes are hard deletes, followed by a vacuum — no tombstones, no trash.

Pause is visible and honest

While paused the menu bar icon is hollow, and Chronicle auto-pauses whenever a deny-listed app is frontmost. It never records “you paused Chronicle from 2 to 4” as a fact about you.

Architecture

Small enough to leave running forever

Chronicle is only useful if it is always on, so the budget comes first and the features fit inside it: under 60 MB resident, under 0.5% CPU at idle, no measurable effect on battery. That budget is why it is a native binary rather than a bundled browser.

Five pieces

Observer — a small daemon with per-OS adapters. Accessibility API on macOS, UI Automation on Windows. No kernel extension, no root, no injection. Event-driven, with a slow heartbeat as backstop.
Normaliser — turns raw observations into three things: an app, an artifact, and a window state. Applies title and URL redaction here, before anything is written, so the sensitive form never reaches disk.
Sessioniser — runs incrementally every 60 seconds over the last two hours, applying the boundary rules. Cheap, idempotent, and safe to re-run after a crash.
Store — encrypted SQLite with FTS5 over titles, paths, and session names. One file, portable, inspectable.
Restorer — the planner plus the adapter table, the only component that acts on the system rather than watching it, and the only one that ever asks for confirmation.

The UI is SwiftUI on macOS and WinUI on Windows over a shared Rust core, so the observer, sessioniser and store are written once.

Crash safety

The daemon writes a heartbeat and a clean-shutdown marker. If the marker is missing at next launch, the last open session is closed at the final heartbeat and flagged as interrupted — which is exactly the session the user is about to come looking for. Observations are written continuously rather than buffered to session end, so a hard power loss costs at most 30 seconds of context.

Multiple machines

Sessions carry a device id and stay on the machine that recorded them. A laptop and a desktop keep separate histories, because a workspace that cannot be restored on this machine is not worth showing here. If cross-device ever ships, it ships as end-to-end encrypted transfer that the user starts by hand — never as an account.

Scope

The features Chronicle will keep turning down

Every one of these is a plausible next feature, a real user request, and a way to stop being the thing that answers “where was I?”

Time tracking

No hours-per-project charts, no productivity score, no weekly report. Chronicle knows how long you spent in Figma and will never tell you about it unprompted.

Screen recording

No screenshots, no timeline of images, no visual memory. Pointers only — it is the reason the whole database is a few megabytes a year.

Clipboard history

A different product with a different threat model. Chronicle restores where you were, not what you copied.

Tasks and notes

No to-dos, no session notes, no tagging system. The session already has a name and a moment in time; that is the whole index.

Team features

No shared sessions, no manager view, no “see what your team worked on”. The instant this data has a second reader, people stop leaving it on.

An assistant

Ask Chronicle answers questions about your own history and stops there. It does not summarise your week, suggest what to work on, or have thoughts about your habits.

The one measure that matters: the time between opening the lid and the first keystroke that is real work. Chronicle is finished when that is under fifteen seconds on a day you cannot remember what you were doing.

Chronicle remembers your workspace so you never have to.
